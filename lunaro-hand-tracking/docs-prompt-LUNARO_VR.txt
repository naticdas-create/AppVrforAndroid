# LUNARO VR — SISTEMA DE REALIDADE VIRTUAL (VR) E REALIDADE AUMENTADA (AR) PARA ANDROID

## 1. VISÃO GERAL DO PROJETO

Quero desenvolver um aplicativo profissional de realidade virtual chamado **LUNARO VR**, inspirado na interface, na experiência visual e na organização espacial do Meta Quest 3.

O aplicativo será desenvolvido principalmente para smartphones Android utilizados em óculos VR Box convencionais.

O objetivo é criar uma experiência de realidade virtual imersiva, moderna, elegante, fluida e tridimensional, que se aproxime visualmente e funcionalmente da experiência do Meta Quest 3 dentro das limitações reais do hardware.

Não quero um simples aplicativo que divide a tela em duas partes e exibe um menu estático.

Quero um verdadeiro ambiente virtual com:
- Interface tridimensional.
- Janelas flutuantes.
- Ambientes imersivos.
- Navegador integrado.
- Teclado virtual 3D.
- Interface espacial.
- Rastreamento de cabeça.
- Rastreamento de mãos quando tecnicamente possível.
- Contorno 3D das mãos.
- Interface que acompanha a mão.
- Interação com janelas no espaço.
- Perspectiva espacial real.
- Aplicativos e ferramentas integrados.
- Possibilidade de utilizar diferentes ambientes virtuais.

O projeto deve ser desenvolvido de maneira modular, profissional e preparado para futuras atualizações.

# 2. HARDWARE E COMPATIBILIDADE

O aplicativo será utilizado em um smartphone Android colocado dentro de um VR Box convencional.

Considerar:
- Giroscópio.
- Acelerômetro.
- Tela do smartphone.
- Câmera frontal e traseira, quando disponíveis.
- Microfone.
- Sensores Android.
- Limitações de processamento.
- Limitações de memória.
- Limitações de rastreamento.
- Diferenças entre modelos de smartphones.

O sistema deve utilizar renderização estereoscópica Side-by-Side, dividindo a imagem em duas visualizações, uma para cada olho.

A interface deve ser ajustada para o uso com lentes de VR Box.

Implementar:
- Configuração de distância entre lentes, quando possível.
- Ajuste de escala visual.
- Centralização da imagem.
- Recentragem da visão.
- Ajuste de conforto.
- Configurações de sensibilidade do giroscópio.
- Correção de distorção óptica, caso seja necessária e compatível com o headset.
- Menu de calibração inicial.

**Não inventar capacidades que o VR Box não possui.**

VR Box convencional normalmente oferece rastreamento rotacional 3DoF, mas não rastreamento posicional 6DoF real.

O aplicativo deve informar claramente quais recursos funcionam nativamente, quais dependem de câmeras externas e quais exigem hardware adicional.

# 4. INTERFACE ESPACIAL WORLD-LOCKED

Implementar um sistema de janelas tridimensionais semelhante ao Meta Quest 3.

As janelas devem existir em posições fixas no ambiente virtual, utilizando coordenadas tridimensionais reais.

Não devem ficar permanentemente presas à câmera.

## Comportamento

Quando uma janela for aberta:
- Ela aparecerá inicialmente à frente do usuário.
- A distância inicial será configurável.
- A janela poderá ser movida.
- A janela poderá ser girada.
- A janela poderá ser redimensionada.
- A janela poderá ser reposicionada no espaço.
- A janela poderá ser minimizada.
- A janela poderá ser fechada.

Depois de posicionada, a janela permanecerá fixa no espaço virtual.

## Efeito de distância e perspectiva

Implementar o comportamento de interface espacial real:

- Se o usuário se afastar da janela, ela permanecerá onde estava.
- A janela parecerá menor naturalmente devido à perspectiva.
- Não reduzir artificialmente a escala da janela.
- Não aumentar a janela para compensar a distância.
- Não fazer a janela acompanhar continuamente a cabeça.
- Se o usuário andar para trás, a janela continuará no mesmo lugar.
- Se o usuário andar para frente, a janela parecerá maior naturalmente.
- Se o usuário observar a janela de lado, deverá enxergar seu ângulo real.
- A janela deve manter sua escala física constante no ambiente virtual.

A mudança aparente de tamanho deverá acontecer exclusivamente devido à perspectiva da câmera.

Não confundir:
- Head-Locked UI: interface presa à cabeça.
- World-Locked UI: interface posicionada no mundo virtual.

O menu inicial pode aparecer diante do usuário, mas as janelas abertas devem poder permanecer no espaço.

**Importante:** não simular rastreamento posicional físico sem suporte do hardware.

Em VR Box convencional, o giroscópio normalmente fornece apenas rotação da cabeça. Para detectar que o usuário realmente andou para trás, será necessário rastreamento posicional compatível, câmera externa, sistema de tracking ou outro recurso adicional.

Caso não exista rastreamento posicional, criar uma alternativa de movimentação virtual e deixar essa limitação clara.

# 5. INTERFACE DA MÃO — HAND-FOLLOWING UI

Criar uma interface tridimensional que acompanhe a mão do usuário.

Essa interface deve funcionar como um painel espacial ligado à palma da mão.

Quando a mão for detectada:
- A interface poderá aparecer sobre ou acima da palma.
- O painel deverá acompanhar a posição da mão.
- O painel deverá acompanhar a rotação da mão.
- O painel deverá acompanhar a orientação da palma.
- O painel deverá acompanhar os movimentos do pulso.
- A interface deverá girar quando o usuário girar a mão.
- A interface deverá se movimentar quando a mão se movimentar.
- O painel deverá permanecer alinhado à mão.

A interface não deve simplesmente seguir a posição da mão.

Ela precisa acompanhar também sua orientação tridimensional.

Utilizar:
- Position.
- Rotation.
- Quaternion.
- Transform.
- Offset configurável.
- Suavização de movimento.
- Correção de orientação.
- Estabilização de tracking.

O painel deverá ter um posicionamento confortável, evitando cobrir completamente a mão.

Implementar opções para:
- Distância do painel em relação à palma.
- Escala.
- Rotação.
- Posição.
- Transparência.
- Sensibilidade.
- Estabilização.

A interface deve acompanhar a mão com baixa latência e sem movimentos bruscos.

Não criar tracking falso. Caso o hardware não consiga detectar a mão, informar a limitação e oferecer uma alternativa.

# 7-B. HAND TRACKING — VISUAL E INTERAÇÃO DIRETA

> Esta seção complementa e, em caso de conflito, tem prioridade sobre as seções 5, 6, 7 e 9 no que diz respeito ao estilo visual das mãos e à forma principal de clicar em elementos.

## Aparência das mãos

Quero que as mãos virtuais tenham um estilo minimalista:

- Contorno predominantemente preto.
- Dedos com tonalidade cinza.
- Articulações identificáveis.
- Visual semelhante a um esqueleto 3D estilizado.
- Sem aparência de mãos humanas realistas.
- Movimento sincronizado com as mãos reais.

O contorno deverá acompanhar dedos, palma e pulso em tempo real.

## Interação direta com interfaces flutuantes

O usuário deverá conseguir clicar diretamente nos elementos da interface utilizando o dedo indicador.

Funcionamento:

1. O usuário estende o dedo indicador.
2. Aproxima o dedo de um botão virtual.
3. Toca diretamente na superfície do botão.
4. O botão responde imediatamente.
5. A ação é executada sem exigir pinça ou confirmação adicional.

A interação deve funcionar em:

- Botões.
- Ícones de aplicativos.
- YouTube, Netflix e outros aplicativos.
- Janelas flutuantes.
- Menus.
- Teclado virtual.
- Configurações.
- Sliders e controles.

## Precisão e resposta

Implementar tracking da ponta do dedo, detecção de contato virtual e raycast 3D.

O sistema deve:

- Responder com a menor latência possível.
- Evitar cliques duplicados.
- Evitar selecionar elementos errados.
- Não exigir movimentos exagerados.
- Manter a correspondência entre o dedo real e o elemento virtual.
- Executar a ação no momento correto do toque.
- Utilizar feedback visual instantâneo.

Quero uma experiência extremamente fluida, intuitiva e confiável, com interação projetada para funcionar em tempo real.

Não utilizar tracking falso ou posições inventadas. A precisão deve ser validada em dispositivos compatíveis, respeitando as limitações de câmera, iluminação e hardware.

O objetivo é obter a experiência mais próxima possível de tocar diretamente em uma interface holográfica.

## Regras de integração com o restante do projeto

- O toque com o indicador (poke) é a interação primária de seleção. A pinça (seção 9) continua sendo usada para agarrar, arrastar, girar e redimensionar janelas, e como seleção à distância via raio a partir da mão.
- O estilo preto/cinza desta seção é o padrão do contorno da seção 6. As opções de cor, espessura, brilho e transparência da seção 6 continuam disponíveis em Configurações, com este estilo como predefinição.
- Evitar toque acidental: considerar a ponta do indicador como "ativa" somente quando o dedo estiver estendido e os demais dedos recolhidos ou relaxados. Usar histerese entre entrada e saída da superfície (ex.: limiar de entrada diferente do de saída), cooldown curto por elemento e zona morta nas bordas dos botões.
- Cada elemento interativo deve expor uma área de toque (collider) com margem mínima confortável, especialmente as teclas do teclado virtual.
- Feedback instantâneo obrigatório: realce do elemento ao aproximar o dedo, indicador de profundidade/proximidade e confirmação visual (e sonora opcional) no momento do contato.
- Sliders e controles contínuos devem manter o dedo "preso" ao controle enquanto houver contato, sem pular de valor.
- Quando a profundidade da ponta do dedo não for confiável (câmera única, pouca luz, mão parcialmente fora do campo de visão), o sistema deve reduzir a confiança, sinalizar a limitação ao usuário e oferecer alternativa (pinça à distância, gaze, controle virtual ou controlador), em vez de inventar a posição.
- A latência de ponta a ponta (captura da câmera → pose da mão → feedback visual) deve ser medida e exibida em um painel de depuração, para que a precisão possa ser validada em aparelhos reais.
- Informar claramente quais aparelhos e acessórios sustentam esta interação: 3DoF com giroscópio apenas não fornece posição das mãos; é necessária uma câmera com visão das mãos (externa ou outro dispositivo) para o toque direto funcionar.

## Referências visuais anexadas

As imagens de referência mostram a interface espacial do Meta Quest OS (Horizon OS): janelas escuras e translúcidas flutuando em arco, barra de aplicativos compacta na parte inferior, botões em estilo pílula, contorno de mão fino sobre o ambiente, e um pequeno indicador circular na ponta do dedo/pinça. Usar como referência de proporção, hierarquia e comportamento, reproduzindo os conceitos de forma original, sem copiar assets proprietários.

# SISTEMA DE REALIDADE AUMENTADA (AR)

Adicionar ao LUNARO VR um sistema completo de **Realidade Aumentada (AR)**, integrado à arquitetura existente e com um modo próprio chamado **LUNARO AR**.

O aplicativo deverá oferecer dois modos principais:
- **LUNARO VR:** experiência VR estereoscópica para VR Box.
- **LUNARO AR:** experiência de realidade aumentada usando a câmera do smartphone, quando o aparelho for compatível.

Não misturar os dois modos de forma artificial. Explicar que, em um VR Box convencional, a câmera do celular normalmente fica bloqueada dentro do headset; portanto, AR com câmera traseira deve funcionar preferencialmente fora do VR Box, salvo quando houver hardware ou configuração compatível.

## Recursos AR desejados

Implementar, quando suportado pelo dispositivo:
- Visualização ao vivo da câmera.
- Detecção de planos horizontais e verticais.
- Detecção de superfícies, como chão, mesas e paredes.
- Colocação de objetos 3D no mundo real.
- Posicionamento, rotação e escala de objetos AR.
- Ancoragem de objetos para que permaneçam no local detectado.
- Interação por toque na tela.
- Seleção, movimentação, rotação, redimensionamento e remoção de objetos.
- Indicador visual de superfície detectada.
- Retícula de posicionamento.
- Botão para colocar objeto.
- Botão para recentrar/reiniciar a sessão AR.
- Interface de configurações AR.
- Alternância entre modo VR e modo AR, com encerramento correto da sessão anterior.

## ARCore e compatibilidade

Avaliar e utilizar **Google ARCore** quando o smartphone for compatível.

Implementar:
- Verificação de compatibilidade ARCore antes de iniciar.
- Verificação de disponibilidade dos serviços necessários.
- Solicitação de permissões de câmera.
- Tratamento de aparelhos incompatíveis.
- Tratamento de falhas de tracking.
- Tratamento de pouca iluminação e superfícies sem textura.
- Mensagens claras quando o tracking não estiver disponível.
- Alternativa sem AR, permitindo continuar usando as funções VR compatíveis.

Não afirmar que todos os smartphones Android suportam ARCore.

Não simular detecção de planos, tracking ou ancoragem quando esses recursos não estiverem funcionando.

## Objetos e experiências AR

Preparar o sistema para inserir objetos 3D no ambiente real, como:
- Painéis virtuais.
- Janelas flutuantes.
- Modelos 3D.
- Elementos decorativos.
- Interfaces do LUNARO VR.
- Conteúdo interativo.

Os objetos deverão permanecer ancorados na posição estimada pelo tracking, respeitando as limitações do ARCore e do dispositivo.

## Arquitetura AR

Criar módulos separados:
- AR Core / AR Session Manager.
- AR Tracking.
- Plane Detection.
- Raycast / Hit Test.
- AR Anchor Manager.
- AR Object Manager.
- AR Interaction.
- AR UI.
- AR Settings.
- AR Android Integration.

Utilizar Unity + C# para a cena e lógica AR quando apropriado, com AR Foundation e ARCore XR Plugin, avaliando as versões compatíveis.

A camada Android nativa deverá ser escrita em **Kotlin (KT), não Java**. Se algum SDK ou plugin exigir uma interface Java, criar somente a ponte estritamente necessária e manter o código nativo do projeto em Kotlin sempre que possível.

## Performance e privacidade

- Priorizar baixa latência e estabilidade.
- Reduzir consumo de bateria e aquecimento.
- Encerrar a câmera quando o modo AR for fechado.
- Não capturar, armazenar ou enviar imagens da câmera sem necessidade e sem consentimento.
- Explicar quais permissões são utilizadas.
- Não manter a câmera ativa em segundo plano sem motivo.
- Respeitar as limitações de câmera, sensores e processamento de cada aparelho.

## Interface do modo AR

Criar uma interface moderna e consistente com a identidade visual LUNARO VR:
- Botão para entrar/sair do AR.
- Estado do tracking.
- Estado de detecção de superfície.
- Seleção de objetos.
- Controles de posição, rotação e escala.
- Recentragem.
- Ajuda rápida.
- Avisos de compatibilidade.

A interface deve permanecer legível sobre a imagem da câmera e não bloquear desnecessariamente a visão do ambiente real.
